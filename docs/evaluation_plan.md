# 평가 계획 (초안)

작성: 2026-10-25 · 상태: 연구자 검토 전 초안

이 문서는 논문용 평가를 위한 두 가지를 정리한다. 하나는 **시험셋을 만드는 방법**이고, 다른 하나는 **사용자 실험 설계**다. 지금까지 쓴 33문장(`data/eval_set_v2.json`)은 결과를 보며 정답과 채점기를 고쳤으므로 개발·회귀용으로만 쓴다.

## 1. 핵심 주장과 검증 대상

> 이벤트를 시간 구조가 명시된 sub-event로 나눈 뒤 생성·합성하면, 단일 프롬프트 생성보다 문장에 적힌 시간 구조(횟수, 순서, 리듬, 상대 세기)가 더 잘 재현되고, 사람도 설명과 더 잘 맞는다고 느낀다.

비교 조건은 아래 두 가지가 기본이다. 필요하면 ablation 결과를 근거로 조건을 더할 수 있다.

| 조건 | 내용 |
|---|---|
| A. 분해 합성 | 기본 플래너(LM 사건 분해, staged) → sub-event별 HapticGen 생성 → 합성 |
| B. 단일 생성 | 같은 문장을 HapticGen에 그대로 입력 (같은 seed, 같은 정규화) |

## 2. 시험셋

### 2.1 원칙
- **개발에 쓰지 않은 문장**만 쓴다. 33개 개발 문장과 같은 동작 계열(예: 드리블→쳐내기, 활 쏘기)도 쓰지 않는다.
- **평가를 시작하기 전에 문장과 정답을 고정**하고, 이후 시스템을 고치면 시험셋으로 다시 재지 않는다. 고칠 필요가 생기면 새 시험셋을 만든다.
- 정답은 **문장에 명시된 조건만** 쓴다. 해석이 필요한 조건이나 렌더링 관습은 채점하지 않는다 (`eval_set_v1_review.md`의 원칙).

### 2.2 문장 출처 (선택 필요)
| 방법 | 장점 | 단점 |
|---|---|---|
| 연구실 외부 참가자가 작성 | 우리 편향이 없음 | 시간 구조가 있는 문장 비율을 통제하기 어려움 |
| 오디오 캡션 데이터셋에서 시간 구조가 있는 캡션 선별 | 대량·공개 데이터 | 소리 중심 문장이라 촉각과 거리가 있음 |
| 연구자가 유형표에 따라 작성 | 유형을 고르게 넣을 수 있음 | 작성자 편향. 시스템 개발자가 아닌 사람이 쓰는 것이 좋음 |

추천: 유형표를 먼저 정하고, **시스템 개발에 참여하지 않은 사람**이 유형마다 문장을 쓴다.

### 2.3 유형 (각 8–12문장 권장)
| 유형 | 예시 형태 | 채점 조건 |
|---|---|---|
| 단일 충격 횟수 | "~를 한 번 친다" | 해당 동작 횟수 |
| 반복 횟수 | "~를 세 번 두드린다" | 해당 동작 횟수 |
| 리듬 | "1초에 두 번씩 ~" | 간격 |
| 순서 | "A 하다가 B" | 순서 |
| 상대 세기 | "약하게 ~, 그다음 세게 ~" | 대응 단계의 세기 비교 |
| 정적 | "~한 뒤 조용해진다" | 마지막 사건 이후 진동 없음 |
| 대조군: 분위기 묘사 | "~한 기분" | 생성 가능 여부만 (분해가 해치지 않는지) |

### 2.4 정답 작성과 검증
- 정답 형식은 `eval_set_v2.json`의 per-event 형식을 따른다.
- 주석자 2명이 독립적으로 작성하고, 불일치는 합의로 정한다. 일치도(조건별 Cohen's κ 또는 단순 일치율)를 보고한다.
- 키워드 패턴 채점은 보조 도구다. 시스템 출력 일부(예: 20%)를 사람이 직접 판정해 자동 채점과의 일치율을 보고한다.

## 3. 객관 평가 (파형)

`scripts/waveform_compare.py`를 시험셋에 적용한다.

- 측정 가능한 조건만 쓴다: 다른 진동이 없는 문장의 **충격 횟수**, **간격**.
- 충돌·물림처럼 사건 하나에 피크가 여러 개 자연스러운 문장은 피크 개수로 채점하지 않는다.
- seed 5개 이상. 문장 단위로 평균한 뒤 조건 간 차이를 쌍체 검정(Wilcoxon signed-rank)으로 본다.
- 충격 검출기는 실제 진동에 대한 정확도가 검증되지 않았다. 사람이 표시한 충격 시각 일부와 비교해 검출기 정확도를 함께 보고한다.

## 4. 사용자 실험 (Quest 3)

### 4.1 설계
- **피험자 내 설계.** 모든 참가자가 A와 B를 모두 경험한다. 제시 순서는 무작위·균형화한다.
- **참가자:** 20–24명 (파일럿 5명으로 효과 크기를 본 뒤 재계산).
- **자극:** 시험셋에서 유형별로 고른 16–24문장 × 조건 2.
- **재생:** 같은 컨트롤러, 같은 세기 정규화(피크 정규화), 양손 또는 주로 쓰는 손 하나로 통일.
- 화면에는 문장만 보여주고 파형은 보여주지 않는다.

### 4.2 과제와 측정
| 과제 | 측정 | 보는 것 |
|---|---|---|
| ① 횟수 맞히기 | 느낀 충격 수를 숫자로 답함 | 시간 구조가 실제로 지각되는가 (객관) |
| ② 일치도 평가 | "설명과 얼마나 맞는가" 7점 척도 | 주관적 일치 |
| ③ A/B 선호 | 같은 문장의 A와 B 중 더 맞는 쪽 | 직접 비교 |
| ④ 사실감 | 7점 척도 | 이음새·부자연스러움 비용이 있는가 |

①은 횟수 문장에만, ②–④는 전체 문장에 쓴다. 대조군(분위기 묘사)에서 A가 B보다 나빠지지 않는지도 본다.

### 4.3 분석
- ① 정확도: 혼합효과 로지스틱 회귀 (조건 고정효과, 참가자·문장 무작위효과).
- ②④ 점수: 혼합효과 모형 또는 Wilcoxon signed-rank.
- ③ 선호: 이항 검정과 문장 유형별 분석.
- 다중 비교 보정을 하고, 효과 크기를 함께 보고한다.

### 4.4 준비할 것
- 실험 진행 UI: 문장 표시 → 재생 → 응답 기록. 지금 웹 UI의 Quest 재생 기능을 재사용한다.
- 세기 보정: 참가자마다 감지 가능한 최소 세기를 확인한다.
- 소음 차단: 컨트롤러 진동 소리가 단서가 되지 않도록 헤드폰과 백색소음을 쓴다.
- 연구윤리 승인(IRB).

## 5. 현재 개발용 결과 요약 (논문 수치 아님)

- 플래너 ablation (33문장, 1회 실행): staged 생성 100% · 조건 통과 81%, 계층 플래너 67% · 28%.
- 파형 비교 (측정 타당 문장 3–4개, seed 3): 분해 합성이 조건 충족 6/18 vs 단일 생성 2/18, 횟수 오차 2.3 vs 5.8.
- 알려진 문제: 0.6초를 넘는 cut 사건을 합성기가 질감으로 처리해 충격이 여러 개 남음. LM이 리듬을 잘못 계산하는 경우가 있음 (c12: 0.3초).
