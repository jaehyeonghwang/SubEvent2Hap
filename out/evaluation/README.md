# 파형 정량 평가: 첫 탐색 결과

기존 저장 결과 11쌍을 평가했다. 새로운 모델 생성이나 가중치 변경은 수행하지 않았다.

## 재실행

```powershell
.\.venv\Scripts\python.exe scripts\eval_waveform.py
.\.venv\Scripts\python.exe -m unittest discover -s scripts -p test_eval_waveform.py
```

기본 결과: `waveform.json`(설정·한계·세부 검출 결과), `waveform.csv`(실행별 지표).
임계값 변경: `--threshold 0.08 --report out/evaluation/threshold008`.
독립 주석 사용: `--references references.json`. JSON은 실행 폴더명을 키로 하고
`{"sub_events": [{"start": 0, "duration": 0.2, "intensity": 1, "transition": "cut"}], "total": 1}`를 값으로 한다.
독립 주석이 없는 실행은 명시적으로 제외한다. 기존 plan의 다른 필드는 필요 없다.

## 결과

| 지표 | Composite | Baseline | 유효 실행 수 |
|---|---:|---:|---|
| 충격 F1 ↑ | 0.799 | 0.229 | 각각 11 |
| 매칭된 충격 onset MAE(ms) ↓ | 11.73 | 48.32 | 각각 11, 7 |
| 목표 강도와 초기 60ms RMS의 Spearman ↑ | 0.966 | 0.057 | 각각 5 |
| 계획의 무음 구간 에너지 비율 ↓ | 0% | 4.37% | 각각 8 |

충격은 `cut`이고 길이 0.6초 이하인 구간으로 근사했다. 실제 WAV의 10ms RMS 증가량으로
onset을 검출하며, 검출 단계는 정답 시점을 보지 않는다. 최소 검출 간격은 80ms,
전역 최대 RMS 대비 문턱은 12%, 일대일 매칭 허용 오차는 100ms이다.
긴 텍스처 구간은 충격 평가에서 제외한다. 전체 문장의 의미와 충격 분류를 자동 판정하지 않는다.
계획 전체 길이에 맞춰 두 파형을 자르거나 0으로 채우므로 합성의 추가 100ms 꼬리는 제외된다.
무음 구간은 crossfade 60ms, 여운 20ms를 허용한다. 강도 상관은 목표 강도가 서로 다른
충격이 3개 이상일 때만 계산한다. 일정 강도 및 무음 등 정의되지 않는 값은 null이다.

검출 임계값 8%, 12%, 20%에서 F1은 각각 composite 0.848/0.799/0.729,
baseline 0.257/0.229/0.216이었다(`sensitivity.json`). 설정에 따른 수치 변화가 있다.
합성 신호, 무음, 누락·추가 충격, 일대일 매칭에 대한 자동 테스트 4개를 통과했다.

## 해석 범위

- 기본 정답은 저장된 생성 계획이다. 합성 방식에 유리한 **계획 충실도** 평가이며 독립적인 텍스트 적합성 평가가 아니다.
- onset MAE는 검출에 성공한 충격만 포함한다. 반드시 F1과 함께 읽는다.
- 저장 결과에는 반복 문장과 서로 다른 계획·설정이 섞여 있고 seed도 통제되지 않았다.
  11개를 독립적인 실험 표본으로 해석하거나 통계적 유의성을 주장하지 않는다.
- 강도 상관은 동일 계획에서 정의된 구간의 측정값이다. 촉각의 감지 강도나 의미 일치도는 아니다.
- 전역 문턱은 약한 후반 충격을 놓칠 수 있다. 연속 텍스처의 변동을 충격으로 오인할 수도 있다.
- 장치의 물리적 출력이나 지각 시뮬레이터는 적용하지 않았다.

## 개선 제안: 우선순위

1. **독립 평가 세트와 구조화된 분해 모델**
   고정 문장, 충격 횟수·감쇠·순서 정답, 별도 합성 평가용 타임라인을 먼저 정의한다.
   개발/평가 문장을 분리하고 문장별 여러 seed를 사용한다. 동일 문장의 실행은 묶어서 집계한다.
   현재 분해기는 silent phase를 여전히 만들 수 있다(예: 공이 정지하는 상태를 지속 진동으로 생성).
   event_type(impact/texture/silent), 반복 횟수, 감쇠비를 명시적으로 예측하게 하고,
   시간 배치와 반복 확장은 결정적인 코드로 처리하는 방식을 제안한다.
   검증에 실패한 계획을 그대로 생성에 넘기지 않는 경로도 필요하다.

2. **후보 선택 개선: 큰 소리보다 목표 구조**
   현재 충격 후보는 attack RMS와 tail/추가 타격으로, 텍스처는 에너지로 선택한다.
   baseline도 가장 큰 RMS 후보를 선택한다. onset 선명도, 단일 충격 여부,
   목표 envelope 및 spectral descriptor를 함께 이용하는 reranker를 제안한다.
   baseline과 composite에 동일 후보 수 또는 계산 예산 조건을 각각 명시한다.
   평가용 검출기만 직접 최적화하면 점수 편향이 생기므로 별도 검출기로 검증한다.

3. **충격과 지속 진동을 다르게 생성**
   현재 짧은 충격도 최소 1.5초 이상 생성한 다음 잘라낸다. 짧은 단일 충격 라이브러리 검색과
   지속 텍스처 생성의 혼합 방식으로 바꾸면 다중 충격 오생성과 생성 비용을 줄일 가능성이 있다.
   기존 repeat 공유를 유지하고 물리적 감쇠·반복 간격 모델로 제어한다.

4. **데이터를 만든 뒤 HapticGen 미세조정**
   caption에 재질, 단일/반복 동작, onset, duration, envelope 정보를 추가하고,
   충격 위치가 정렬된 데이터와 반복 패턴을 구성한다. 토큰 기반 생성기의 학습 loss와 함께
   held-out WAV의 구조 지표를 검증한다. 파형 envelope/STFT loss를 직접 추가하려면
   codec 디코더를 통과하는 미분 경로와 학습 구조 검토가 필요하다.
   생성 샘플에 대한 단순 순위 선택부터 검증한 후 가중치 미세조정으로 확장한다.

5. **장치 및 지각 모델 보정**
   현재 gamma=1.6은 설정값이며 사용자·장치에 보정된 지각 법칙으로 검증된 값이 아니다.
   Quest 컨트롤러를 가속도계로 측정해 주파수 응답·포화·지연을 모델링하고 출력 파형을 평가한다.
   기준 진동이 있으면 ST-SIM 등 full-reference 방법을 추가할 수 있지만 텍스트 의미 지표로 사용하지 않는다.

HapticGen 논문 역시 시간적 특성을 포함한 recaptioning과 객관적 촉각 지표의 필요성을 설명한다.
https://hapticgen.hcitech.org/static/pdfs/paper.pdf

ST-SIM은 기준 대비 spectral/temporal 품질 평가 연구이다.
https://pubmed.ncbi.nlm.nih.gov/31880560/
